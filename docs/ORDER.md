## §0. プロジェクト概要

- YouTubeの「今の勢い」をランキングで一覧できる**導入口アプリ**。動画タップで本家YouTubeへ転送する。動画の閲覧・埋め込み再生はしない。
- 核となる体験＝**「みんな⇄自分」の往復ザッピング**。全員が同じものを見る公式ランキング（みんな）と、端末内学習のMyランキング（自分）をタブで行き来する。YouTube本体はパーソナライズ（自分）しか出さず、その学習もブラックボックス——という不満への回答。
- 世界展開前提。UIは英語ベース＋日本語切替。
- レイアウトの参照は「2010年代のランキング文化の一覧性・お祭り感」。ただし**ニコニコ動画等の見た目の模倣はしない**（機能面の参考のみ）。

## §1. 自走ルール（最重要・常時遵守）

1. **止まらない**: 人間ゲート（§7）以外で発注者に質問しない。判断に迷ったら (a)本書 → (b)DECISIONS.md → (c)最も安く後戻りできる選択肢、の順で自己解決し、判断を DECISIONS.md に1行追記する。
2. **引き継ぎメモ常備**: `HANDOFF.md` を常に最新化する。内容は「現在地／次の一手／未解決」を各3行以内。セッションが切れても ORDER＋HANDOFF だけで即再開できる状態を維持する（再開コスト最小化）。
3. **小さく進む**: 機能単位の小さなコミット。Conventional Commits。フェーズ完了ごとに git タグ。
4. **自己検収**: 各フェーズの検収基準（§6）を自分で実行し、全通過してから次へ。失敗は修正リトライ最大5回。5回で通らない項目は `BACKLOG.md` に理由付きで積み、**全体は止めずに先へ進む**。
5. **人間ゲートの扱い**: ゲートに当たったら `NEEDS_HUMAN.md` に「発注者にやってほしい操作」をコピペ可能な手順粒度で書き、そのゲートに依存しない作業を続ける。依存しない作業が尽きた時のみ停止してよい（停止時はHANDOFF.mdに明記）。
6. **UI変更後は必ずデザイン監査**: UI（HTML/CSS/JSの表示に関わる変更）を含むコミットの後は、必ず `design-reviewer` サブエージェント（§5）を起動し、Critical指摘をゼロにしてから次の機能へ。1機能あたり監査は最大3巡。3巡で残った非Critical指摘はBACKLOG.mdへ（磨きの無限ループ禁止）。
7. **秘密情報**: APIキー等はGitHub Secrets（`YT_API_KEY`ほか）のみ。コード・コミット履歴・ログに平文で残さない。

## §2. 確定仕様

### v1（公開ライン）
1. **期間切替ランキング**: 24時間／週間／月間／年間／全期間。定義＝「**その期間内に投稿された動画の再生数順**」上位100件。
2. **動画／ショート部門切替**（全ランキング共通）。ショート判定: 長さ≤3分を候補とし、`https://www.youtube.com/shorts/{videoId}` の有効性確認で確定（API割当を消費しない）。数%の誤判定は許容。実装方式（videoDurationフィルタ併用等）は任せる。
3. **カテゴリ別タブ**: YouTube公式videoCategory準拠。総合＋主要カテゴリ（音楽／ゲーム／エンタメ等、5個程度から）。**割当の都合でまず24時間のみ**。
4. **国切替**: JP／US。構造はn国対応にし、設定ファイル1箇所で増減できること。
5. **i18n**: 英語ベース＋日本語切替。全文言を辞書ファイルに分離。
6. **ランキングカード**: サムネイル／順位／再生数／チャンネル名／投稿からの経過時間／順位変動マーク（前回集計比の↑↓NEW）。
7. **スワイプザッピング**: 隣接タブ（期間・部門・カテゴリ・国）へスワイプで移動。
8. **転送**: タップで本家YouTubeへ。動画は `watch?v=`、ショートは `shorts/` のURL（アプリがあればアプリで開く標準リンク挙動でよい）。
9. **ネイティブ広告カード枠**: リスト8件ごとに1枠。（**改訂 2026-08-25**: 発注者指示により**10件ごと**に変更。煩わしさを抑えつつ表示は維持する）v1はプレースホルダ実装（"AD"表記のダミーカード）。審査通過後に広告タグを差し込むだけの構造にしておく。
10. **PWA**: manifest＋Service Worker。オフライン時は直近キャッシュを表示。

### v2
11. **端末内学習のMyランキング**: 表示ログ×タップログから興味スコアを作りMyタブに表示。学習内容は**一覧で見える・個別に消せる・重みをいじれる**（YouTubeのブラックボックスへの対抗が価値の核）。データはlocalStorage/IndexedDBのみ、**外部送信は一切しない**。
12. **タグ・頻出ワードの勢いランキング**: タイトル＋タグの自前集計。言語別ストップワード除去。
13. **世界地図タブ**: 各国1位のサムネを地図上に配置し、タップでその国のランキングへ潜る。更新は1日1〜2回で足りる。
14. **「伸び」ランキングの解禁**: スナップショットが貯まり次第、「期間内に再生数が伸びた動画」（投稿日不問）定義を24h／週間／月間に追加。**年間・全期間は投稿日ベース定義のまま**（§8の保存30日制約のため）。蓄積日数が足りるまでは自動的に非表示→足りたら自動有効化される実装にする。

### v3
15. **匿名タップ集計**: 「このアプリ経由で今日◯人が飛んだ」独自指標＋世界地図への重ね表示（アプリ住民の地図）。Cloudflare Workers＋KV（無料枠）で受ける。保存するのは**国コード＋動画ID＋日付のカウンタのみ**。個人特定情報・IP保存は不可。
16. **Android化**: Capacitorで包んでPlay配信。AdMobネイティブ広告の差し込み。Web側はAdSenseインフィード。
17. **文字コミュニティは実装しない**（保留のまま。勝手に着手しない）。

## §3. 技術構成（確定）

- **収集**: GitHub Actions cron → Node 20スクリプト → YouTube Data API v3 → `public/data/*.json` 生成 → デプロイ。
- **フロント**: 素のHTML/CSS/JS（フレームワーク・ビルド工程なし）。発注者が単一ファイルの差分ループで手を入れられる構成を優先する。
- **ホスティング**: GitHub Pages。
- **v3のみ**: Cloudflare Workers＋KV。
- **Android**: Capacitor。
- **テスト**: Playwright（E2E＋スクリーンショット）。
- APIキー未着の間は**モックJSONで全UI開発を先行**する（P0から着手可能）。

## §4. 収集仕様とAPI割当予算

- 割当は既定10,000units/日。`search.list`=100units、`videos.list`=1unit（50件/回）。
- 期間ランキング取得の基本形: `search.list`（publishedAfter, order=viewCount, regionCode, 部門フィルタ）→ id列 → `videos.list` でstatistics取得 → 再生数順に整列。
- 更新頻度: **24h＝毎時／週間・月間＝日次／年間・全期間＝週次／世界地図＝日次**。
- 実装時に「国×部門×期間×カテゴリ」の消費予算表を算出しREADMEに記載。**日次消費が8,000units（80%）を超える構成になった場合は自動で更新頻度を落とすセーフガード**を収集スクリプトに入れる。
- 国・カテゴリを増やす変更は、予算表を更新してから行う。

## §5. デザイナーサブエージェント（UI監査の常設）

`.claude/agents/design-reviewer.md` を以下の内容で作成する。§1-6の通り、UI変更を含む全コミット後に必ず起動する。

```markdown
---
name: design-reviewer
description: UI（HTML/CSS/JSの表示に関わる部分）を変更した直後に必ずPROACTIVELYに起動するデザイン監査エージェント。スクリーンショットを撮り、docs/ORDER.md §5のデザイン憲章に照らして指摘リストを返す。
tools: Read, Glob, Grep, Bash
model: inherit
---
あなたはこのプロジェクト専属のUIデザイン監査者。手順:
1. ローカルサーバーを起動し（例: `npx serve public`）、Playwrightで
   360×800（基準・Android縦）と412×915の2サイズでスクリーンショットを撮る。
2. 撮影対象の状態: 各タブ（期間／部門／カテゴリ／国／My／地図）、ロード中（スケルトン）、
   データ空、エラー、極端に長いタイトル、広告枠、英語UIと日本語UIの両方、ライト／ダーク両テーマ。
3. docs/ORDER.md §5「デザイン憲章」に照らして評価し、次の形式で返す:
   - Critical（次に進む前に必ず修正）／Should（今回直すべき）／Nice（BACKLOG候補）
   - 各指摘に該当ファイル・該当箇所と、具体的な修正案を1行添える。
4. 憲章にない美的判断は「一覧性」「ザッピングの速度感」を最優先に裁定する。
```

### デザイン憲章（このアプリの「良い」の定義）
- **一覧性が正義**: ファーストビューに最低4件。サムネ主役、順位数字は大きく。情報密度は高く、整列で秩序を保つ。
- **ザッピングの速度感**: タブ切替・スワイプは体感即時（スケルトン表示、アニメは短く）。
- 順位変動↑↓NEWは色で瞬読できる（上昇＝緑系／下降＝グレー／NEW＝アクセント色）。
- タップ目標44px以上。主要操作は片手・親指圏。
- ライト／ダーク両対応。コントラストはWCAG AA。
- 広告カードはコンテンツと明確に区別（"AD"表記）しつつ、リストのリズムを壊さない。
- 英日どちらのUIでも文字がはみ出さない・崩れない。
- 「祭りの熱っぽさ」を少量の演出で（例: 1位の特別扱い）。特定サービスの見た目の模写はしない。

※この憲章は発注者がいつでも差し替える。差し替えられたら既存UI全体を新憲章に追随させる。
※発注者本人のスクショ指摘（人間ゲートD）は憲章より常に優先。

## §7. 人間ゲート一覧（ここだけ発注者の手が要る）

- **A（P1着手時）**: Google Cloudでプロジェクト作成→YouTube Data API v3を有効化→APIキー発行→キー制限設定→`YT_API_KEY`としてGitHub Secretsに登録。NEEDS_HUMAN.mdに画面手順を書く（所要30分想定）。
- **B（P5着手時）**: Cloudflareアカウント作成＋wrangler認可。
- **C（P6）**: Google Play Console登録（$25）／AdMob・AdSense申請（審査は数日〜数週間）。申請文・ストア掲載文・プライバシーポリシーは全部こちらで用意し、発注者は提出操作のみ。
- **D（随時・任意）**: 見た目の最終差分測定。発注者のスクショ指摘はデザイン憲章より優先して反映する。

ゲート待ちの間も、依存しない作業（モックでのUI、E2E整備、i18n、地図、学習ロジック等）を進めて止まらない。

## §8. 規約・法務ガード（違反する実装の禁止）

- **YouTube API Services利用規約に準拠**:
  - APIデータへのアクセスの販売・課金は不可（収益は広告のみ）。
  - プレイヤーの埋め込みはしない設計だが、仮に将来入れる場合もプレイヤー上・周辺への広告重畳や再生前インタースティシャルは不可。
  - 各動画からYouTube本体へのリンク（転送導線）を維持する。YouTube API利用の帰属表示をアプリ内に置く。
  - **取得したAPIデータの保存は30日以内にリフレッシュまたは削除**。時系列スナップショットは31日で自動削除するジョブを入れる。表示は常に最新集計から生成。
- 名称・ロゴで「YouTube」を模倣・僭称しない。サードパーティ製であることをアプリ内に明記。
- プライバシーポリシーページを同梱（雛形生成でよい）。EU向け同意表示（Google UMP）はP6で実装。
- v2学習データは端末外に送信しない。v3集計は匿名カウンタのみ（IP・個人識別子の保存不可）。
