# docs/BUDGET.md — API 割当予算表（ORDER §4）

**結論: 既定構成の消費は 1日あたり 7,125 units（既定割当 10,000 の 71.2%）。**
ソフト上限 8,000 units(80%) の下に収まっている。国・カテゴリを増やすときは
**この表を更新してから** `public/js/config.js` を触ること。

---

## 1. 単価

| 呼び出し | 単価 | 1回あたり取得数 |
|---|---:|---:|
| `search.list` | 100 units | 50 件 |
| `videos.list` (id 指定・statistics) | 1 unit | 50 件 |
| `videos.list` (chart=mostPopular) | 1 unit | 50 件 |
| `/shorts/{id}` の HTTP 到達性チェック | **0 units** | 1 件 |

1本のランキング（上位 N 件）の費用 = `ceil(N/50) × (100 + 1)`

| 件数 | ページ | 費用 |
|---:|---:|---:|
| 50 | 1 | **101 units** |
| 100 | 2 | **202 units** |

|---|---|---:|---:|---:|

## 3. 既定スケジュールと日次消費

| ジョブ | 既定間隔 | 1日の実行回数 | 日次 units |
|---|---|---:|---:|
| `top24h` | 6時間ごと | 4 | 3,232 |
| `weekmonth` | 日次 | 1 | 1,616 |
| `categories` | 日次 | 1 | 2,020 |
| `yearall` | 週次 | 1/7 | 231 |
| `map` | 日次 | 1 | 26 |
| | | **合計** | **7,125 / 10,000 (71.2%)** |

残り 2,875 units はリトライ・手動実行・ショート判定の再確認の余裕。

### ORDER §4「24h＝毎時」との差分（重要）

毎時にすると `top24h` だけで **808 × 24 = 19,392 units/日** となり、既定割当 10,000 を
単独で倍近く超える。物理的に不可能なので **既定は 6時間ごと**とした（DECISIONS.md 参照）。

**割当を増やせば自動で毎時に近づく。** `config.js` の `QUOTA.dailyUnits` を上げるだけで、
planner（`scripts/lib/plan.mjs`）が `top24h` の間隔を 6h → 4h → 3h → 2h → 1h と詰める。

| `QUOTA.dailyUnits` | 到達する `top24h` 間隔 | 日次消費 |
|---:|---|---:|
| 10,000（既定） | 6時間 | 7,125 |
| 15,000 | 3時間 | 10,357 |
| 20,000 | 2時間 | 13,589 |
| 30,000 | 1時間（ORDER の理想） | 23,285 |

割当の増枠は Google の
[YouTube API Services Audit form](https://support.google.com/youtube/contact/yt_api_form)
から申請する（無料・審査あり）。急ぎでなければ 6時間間隔のままで v1 公開に支障はない。

## 4. セーフガードの挙動（ORDER §4 の要件）

`scripts/lib/plan.mjs` が毎回の実行前に走る。

1. `config.js` の構成から**日次消費見込み**を算出する。
2. 見込みが `dailyUnits × 0.8` を超えていたら、**priority の大きいジョブから間隔を倍**にして
   収まるまで落とす（`floorHours` が下限。それでも収まらなければジョブを当日スキップ）。
   落とした事実は `public/data/index.json` の `quota.degraded = true` に出て、UI のフッタにも出る。
3. 逆に十分な余裕がある場合は `priority` の小さいジョブ（＝ `top24h`）から間隔を詰める。
4. 実際の消費は `public/data/_budget.json` に積算し、**PT 0:00 でリセット**する。
   当日の実消費が `dailyUnits × 0.95` に達したら、その日は残ジョブを実行しない（ハード停止）。

### 国を1つ増やしたときの見積り（自動計算されるが目安）

| 国数 | 日次 units | 判定 |
|---:|---:|---|
| 2（既定） | 7,125 | ✓ |
| 3 | 10,687 | ✗ → `categories` が日次→2日ごとに自動降格して 9,677 → さらに `yearall` 降格… |
| 4 | 14,250 | ✗ → 大幅降格。割当増枠が実質必須 |

**目安: 既定割当のままなら 2カ国が上限。** 3カ国以上は増枠申請とセットで行うこと。
