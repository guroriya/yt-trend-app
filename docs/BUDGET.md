## 3. 既定スケジュールと日次消費

planner（`scripts/lib/plan.mjs`）が自動で決める実効間隔。**この表は planner の出力そのもの**で、
`node scripts/collect.mjs --dry-run` を実行すればいつでも再確認できる。

| ジョブ | 実効間隔 | 1日の実行回数 | 日次 units |
|---|---|---:|---:|
| `top24h` | 8時間ごと | 3 | 4,848 |
| `weekmonth` | 3日ごと | 1/3 | 1,077 |
| `categories` | 7日ごと | 1/7 | 577 |
| `map` | 日次 | 1 | 26 |
| `catweekmonth` | 14日ごと | 1/14 | 577 |
| `yearall` | 7日ごと | 1/7 | 462 |
| `catyearall` | 30日ごと | 1/30 | 269 |
| | | **合計** | **7,837 / 10,000 (78.4%)** |

残り 2,163 units はリトライ・手動実行・`videos.list` の取り直しのための余裕。
（ショート判定の HTTP 確認は 0 units なのでここには含まれない。）

**「まず取れる」を優先した設計**: 新しい期間・カテゴリのデータは、最初の1周が終わるまで
前回のファイル（無ければ空）を表示する。planner が間隔を延ばすのは *更新頻度* であって、
*初回取得* ではない（未取得のリストは due になった時点で必ず取りにいく）。

### ORDER §4「24h＝毎時」との差分（重要）

4カ国では `top24h` 単独で **1,616 × 24 = 38,784 units/日**。既定割当 10,000 では届かない。
**既定は 8時間ごと**（2カ国時代は6時間ごとだった）。

**割当を増やせば自動で詰まる。** `config.js` の `QUOTA.dailyUnits` を上げるだけで、
planner が重要なジョブから間隔を詰める（コードの変更は不要）。

| `QUOTA.dailyUnits` | `top24h` | `categories` | `catweekmonth` | 日次消費 |
|---:|---|---|---|---:|
| 10,000（既定） | 8時間 | 7日 | 14日 | 7,837 |
| 15,000 | 6時間 | 7日 | 7日 | 11,954 |
| 20,000 | 6時間 | 日次 | 7日 | 15,955 |
| 30,000 | 4時間 | 日次 | 2日 | 22,650 |
| 50,000 | 2時間 | 日次 | 日次 | 36,386 |
| 100,000 | **1時間**（ORDER の理想） | 日次 | 日次 | 55,778 |

割当の増枠は Google の
[YouTube API Services Audit form](https://support.google.com/youtube/contact/yt_api_form)
から申請する（無料・審査あり）。**有料での追加割当は提供されていない**（2026-08 時点。
YouTube Data API は従量課金メニューを持たず、増枠は審査ベースの無料申請のみ）。
急ぎでなければ現行間隔のままで v1 公開に支障はない。

## 4. セーフガードの挙動（ORDER §4 の要件）

`scripts/lib/plan.mjs` が毎回の実行前に走る。

1. `config.js` の構成から**日次消費見込み**を算出する。
2. 見込みが `dailyUnits × 0.8` を超えていたら、**priority の大きいジョブから間隔を倍**にして
   収まるまで落とす（`floorHours` が下限。それでも収まらなければジョブを当日スキップ）。
   落とした事実は `public/data/index.json` の `quota.degraded = true` に出て、UI のステータスバーにも出る。
3. スキップまで行った場合でも、**空いた枠に収まる安いジョブは最低頻度で復活させる**
   （例: `map` は 26 units/日なので、重いジョブの巻き添えで消えない）。
4. 逆に十分な余裕がある場合は `priority` の小さいジョブ（＝ `top24h`）から間隔を詰める。
5. 実際の消費は `state/_budget.json` に積算し、**PT 0:00 でリセット**する。
   当日の実消費が `dailyUnits × 0.95` に達したら、その日は残ジョブを実行しない（ハード停止）。

### 構成を変えたときの目安

| 構成 | 日次 units | 判定 |
|---|---:|---|
| 2カ国・カテゴリ24hのみ（旧） | 7,125 | ✓ 余裕あり |
| **4カ国・カテゴリ全期間（現行）** | **7,837** | ✓ 収まる（ただし更新間隔は延びる） |
| 6カ国・カテゴリ全期間 | 11,700 見込み | ✗ 大幅降格。増枠申請とセットで |

**国やカテゴリを増やすときは、必ず `node scripts/collect.mjs --dry-run` で実効間隔を確認してから。**
「取れる本数」は増えても「1本あたりの鮮度」は落ちる、というトレードオフになる。
