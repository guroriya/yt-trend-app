（既定割当 10,000 の 78.2%）。バックフィル進行中は 定常 6,397 ＋ 予約 1,440 ＝ 7,837 units。**

> 「24時間ランキングは当面毎日1回でよい。浮いた予算で国別を強く」——
> top24h は `desiredHours: 24` のキャップで毎日に固定し、IN/BR を足して6カ国に、
> 世界地図を60カ国に拡充し、全期間ランキングの遡り収集（バックフィル）を追加した。

## 2. ジョブ別の1回あたり費用（現行構成: **6カ国 × 2部門**・カテゴリは**全期間**）

> **不変条件（60日シミュレーションが守る）: どのジョブも1回の費用 < 1日のハード停止（9,500）。**
> 2026-08-26 から周回は実行をまたいで閉じるので、破っても飢餓はしなくなったが、
> 1周が複数日にまたがってリストの取得時刻がまだらになり、更新間隔の約束より鮮度が落ちる。
> 6カ国化で旧 catweekmonth / catyearall（12,120 units）がこれを破ったため、期間単位の

## 3. 既定スケジュールと日次消費

planner（`scripts/lib/plan.mjs`）が自動で決める実効間隔。**この表は planner の出力そのもの**で、
`node scripts/collect.mjs --dry-run` を実行すればいつでも再確認できる。

| `categories` | 7日ごと | 866 |
| `map` | 日次 | 60 |
| `catweek` | 7日ごと | 866 |
| `catmonth` | 14日ごと | 433 |

| `catyear` | 30日ごと | 202 |

| `poolrefresh` 予約 | 毎日 | 40 |
| | **合計** | **7,863 / 10,000 (78.6%)** |

### 3-b. バックフィル進行中（`BACKFILL.enabled` かつ未完走）

予約 1,440 units/日（窓 1,400 ＋ refresh 40）をソフト上限から差し引くので、
定常ジョブは自動で控えめになる: weekmonth 3日／catweek・catmonth 14日／year系 30日 ＝ **6,397**。
合計 6,397 ＋ 1,440 ＝ **7,837 / 10,000 (78.4%)**。
完走すると予約が 40 に縮み、**何もしなくても 3-a の間隔に自動昇格**する。

### 3-c. バックフィルの一過性費用

窓 = 動画 2005年〜（直近2年は半年割・24窓）＋ショート 2020年〜（9窓）＝ **33窓/国**。
6カ国 × 33窓 × 101 units ≒ **20,000 units（一度きり）** → 1,400/日 で **約15日で完走**。
国を後から足すと、その国の窓だけが自動で歩き直しになる（+33窓 ≒ 3,333 units/国）。

### ORDER §4「24h＝毎時」との差分（重要・第3弾で方針変更）

旧方針の毎時更新は 6カ国では top24h 単独で 2,424×24 ＝ 58,176 units/日 を要する。
**発注者指示（2026-08-25 第3弾）で「24h は毎日1回・浮いた予算で国別強化」に変更した。**
`top24h` の `desiredHours: 24` がそのキャップで、増枠しても 24h は毎日のまま、
余りは weekmonth → categories → catweek … の順（priority 順）に流れる。
再び高頻度にしたくなったら `config.js` の `top24h.desiredHours` を小さくするだけ。

**割当を増やすと何が変わるか**（`QUOTA.dailyUnits` を書き換えるだけ。コード変更不要）:

| `QUOTA.dailyUnits` | `weekmonth` | `categories` | 日次消費 | 備考 |
|---:|---|---|---:|---|
| 10,000（既定） | 2日 | 7日 | 7,823 | 6カ国の現行 |
| 15,000 | **毎日** | 2日 | 11,978 | |
| **20,000（ゲートFの申請額）** | **毎日** | **毎日** | 15,874 | **8カ国（+FR/DE）にしてもこの枠に収まる** |
| 30,000 | 毎日 | 毎日 | 23,809 | catweek/catmonth も毎日〜2日に |

8カ国化の手順: `QUOTA.dailyUnits: 20000` ＋ `COUNTRIES` に FR/DE を追記（`SEARCH_Q.fr/de` は準備済み）。
バックフィルは FR/DE の窓だけ自動で再開する（+6,700 units・数日）。

割当の増枠は Google の
[YouTube API Services Audit form](https://support.google.com/youtube/contact/yt_api_form)
から申請する（無料・審査あり・数週間）。**有料での追加割当は提供されていない**（2026-08 時点。
YouTube Data API は従量課金メニューを持たず、増枠は審査ベースの無料申請のみ）。
申請文面は `docs/SUBMISSIONS.md` §5、手順は `NEEDS_HUMAN.md` ゲートF。

## 4. セーフガードの挙動（ORDER §4 の要件）

`scripts/lib/plan.mjs` が毎回の実行前に走る。

1. `config.js` の構成から**日次消費見込み**を算出する。バックフィルの予約
   （`reservedUnits`）はソフト上限から先に差し引く。
2. 見込みが `dailyUnits × 0.8 − 予約` を超えていたら、**priority の大きいジョブから間隔を倍**にして
   収まるまで落とす（`floorHours` が下限。それでも収まらなければジョブを当日スキップ）。
   落とした事実は `public/data/index.json` の `quota.degraded = true` に出て、UI のステータスバーにも出る。
3. スキップまで行った場合でも、**空いた枠に収まる安いジョブは最低頻度で復活させる**
   （例: `map` は 60 units/日なので、重いジョブの巻き添えで消えない）。
4. 逆に十分な余裕がある場合は `priority` の小さいジョブから間隔を詰める
   （`desiredHours` が上限キャップ。top24h=24 が「毎日でよい」の実装）。
5. 実際の消費は `state/_budget.json` に積算し、**PT 0:00 でリセット**する。
   当日の実消費が `dailyUnits × 0.95` に達したら、その日は残ジョブを実行しない（ハード停止）。
   バックフィルは加えて自分の予約（`BACKFILL.dailyUnits`）でも自己制限する。

### 構成を変えたときの目安

| 構成 | 日次 units | 判定 |
|---|---:|---|
| 4カ国・カテゴリ全期間・24h=8時間ごと（旧） | 7,837 | ✓（第2弾時点の構成） |
| **6カ国・カテゴリ全期間・24h=毎日（現行）** | **7,823** | ✓ 収まる |
| 8カ国・同上（増枠前に先行しても） | 8,509→planner が自動降格 | △ 動くが遅くなる。増枠とセットで |
| 8カ国・増枠 20,000 | 15,874 | ✓ ゲートF後の目標構成 |

**国やカテゴリを増やすときは、必ず `node scripts/collect.mjs --dry-run` で実効間隔を確認してから。**
「取れる本数」は増えても「1本あたりの鮮度」は落ちる、というトレードオフになる。
増やした国のバックフィル窓も自動で積まれる（+33窓 ≒ 3,333 units/国）ことも忘れずに。
